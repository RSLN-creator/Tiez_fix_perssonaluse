# TieZ Frontend Code Review — Structure, Comments, Security, Performance

Scope: `src/` of the TieZ clipboard manager (React 19 + TypeScript + Vite 7 + Tauri 2.10).
Reviewed: all 120 source files under `src/` plus `package.json`, `tsconfig.json`, `vite.config.ts`, `index.html`.
All paths below are relative to `tiez_src/`; line numbers were re-verified against the files.

---

## 1. Executive summary

The frontend is feature-complete and well-organized at the folder level (feature slices + `shared/hooks` + `shared/lib` + CSS-variable theming), with good fundamentals: only **one** `innerHTML` assignment in the whole codebase (`HtmlContent.tsx:232`), zero `dangerouslySetInnerHTML` usages, no secrets in `localStorage`, real virtualization (Virtuoso) for the main list, a custom `memo` comparator on the hot list item, and the only test file covers the security-sensitive masking util.

The dominant architectural problem is **state/props plumbing**: ~145 `useState` calls live in a single `useAppState` hook whose 200+ fields are destructured in `App.tsx` and then re-threaded through a 200-field prop object (`useSettingsPanelProps`) into a ~130-prop `SettingsPanel` and 11 group files. Because the props object is rebuilt every render and `LabelWithHint` is defined inside the render body, `memo(SettingsPanel)` never bails and settings subtrees remount on every App render (i.e., every search keystroke). The second dominant problem is **copy-paste duplication**: the entire rich-text preview pipeline (≈350 lines incl. the decision cascade and fallback timers) exists twice in `ClipboardItem.tsx` and `CompactPreviewWindow.tsx`, the HTML sanitizer exists twice, the settings-row markup is hand-duplicated ~60 times across the group files, and `TagManager.tsx` embeds ~1,230 lines of CSS in JSX while a `tag-manager.css` file also exists.

Security posture is "hand-rolled but thoughtful": clipboard HTML is sanitized before injection, but the sanitizer is incomplete (no removal of `iframe/object/embed`, `javascript:` checked only as a plain prefix, non-Office `<style>` kept) and clipboard HTML can force `convertFileSrc()` on arbitrary local paths, so a malicious copied webpage can probe/read local files as images. Announcement links and file-transfer peer paths are opened through the native opener without scheme validation at the frontend.

Comment norms are mixed: comments are mostly concise English with good inline explanations in the complex files, but there is dead commented-out code, hardcoded-`false` debug scaffolding, unguarded `console.log` debug spam in production (`FileTransferChatView`), and dozens of hardcoded Chinese/English UI strings that bypass the `t()` system (including a stale hardcoded version string "正在同步 0.3.4" in `SettingsFooter.tsx:162`).
